## Summary

## Post-Deploy Validations Required (after apply)

1. `aws rds describe-db-instances --db-instance-identifier devops-ia-production` returns `DBInstanceStatus: available`
2. Confirm `StorageType: gp3`, `StorageEncrypted: true`, `IAMDatabaseAuthenticationEnabled: true`
3. Replace `PLACEHOLDER_IRSA_ROLE_ARN` in `serviceaccount.yaml` with the value of Terraform output `backend_irsa_role_arn`
4. Replace `PLACEHOLDER_RDS_ENDPOINT` in `configmap.yaml` with the value of Terraform output `db_instance_address`
5. Create the IAM DB user in PostgreSQL (one-time runbook step, not managed by Terraform):
   ```sql
   CREATE USER app_user;
   GRANT rds_iam TO app_user;
   GRANT CONNECT ON DATABASE devops_ia TO app_user;
   GRANT USAGE ON SCHEMA public TO app_user;
   GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO app_user;
   GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO app_user;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO app_user;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO app_user;
   ```
6. Confirm ArgoCD PreSync Job completes with `Succeeded` before deployment pods roll out
7. Confirm `/backend/health` returns `{ db: "connected" }` after rollout

## Deviations from ADR

- **OIDC provider lookup via data source**: ADR-0014 says OIDC provider is in stack 04, but stack 04 does not expose it as an output. Stack 05 resolves it via `data "aws_iam_openid_connect_provider"` using the EKS cluster issuer URL. This is a read-only lookup and does not create or duplicate the resource. It matches the pattern used in stack 04's own `aws-lbc.iam-role.tf`.
- **Egress rule on RDS SG**: added an explicit deny-all egress rule (scoped to 127.0.0.1/32) to RDS security group. RDS instances do not initiate outbound connections; this makes the intent explicit and passes Checkov `CKV_AWS_382`.
- **`enabled_cloudwatch_logs_exports`**: ADR-0013 marks this as optional but recommended. Added `["postgresql"]` to comply with the security/observability guidance in the ADR and to satisfy Checkov scans without needing a `checkov:skip` comment.
